# Public market indicator catalog

The website’s **3년 추이 보기** entries share `market-chart-history.json`. FX, oil, cryptocurrency, government yields, economic statistics and the national margin lending total have a three-year view. The initial margin history uses the FreeSIS daily export titled `신용공여 잔고 추이` and its `신용거래융자 / 전체` column. To import another official XLSX when refreshing history locally, install `openpyxl` and set `KOFIA_CREDIT_XLSX` to the file outside the public tree. The scheduled job appends verified headline balances and can check recent corrections through the official interval API when `DATA_GO_KR_SERVICE_KEY` is configured. The chart uses settlement dates and shows gaps in the source.

`data/market-indicator-catalog.json` is generated from already published JSON artifacts by `python scripts/export_market_indicator_catalog.py`; it never opens the private SQLite cache or fetches a provider. The daily forecast workflow runs it after its existing collectors and publishes only the reviewed catalog path. Failed collectors leave their prior public artifacts in place; the catalog generation timestamp therefore does not imply fresh observations. Before replacing the catalog, the CLI checks required artifact schemas and market coverage; validation or generation failure leaves the last-good catalog intact. A custom output path reads the existing public catalog as its seed without modifying it.

The `market_indicator_catalog_v1` document contains dynamic `series`, `events`, `releases`, and `model_links`. Each series carries its stable ID, Korean category and label, source, unit, date basis, status, source receipt timestamp where known, chart kind, optional release dates/URLs, and ordered `[date, number]` points. `missing_dates` lists explicit nulls in the source; other absent dates are unknown and must not be interpolated or treated as trading days. The status is source-reported when available, otherwise `unknown`. Sparse snapshots use `chart_kind: points`, so unobserved dates are never connected. CFD disclosed-name aggregates are distinct from FreeSIS with/without margin totals, which include overseas positions; stale source statuses are retained.

The initial snapshot history was built from 11 reachable published `origin/master` Git revisions of `unofficial_numerics.json` and `market_indicators_status.json`, keeping only observations whose source and unit match the current definition. Future runs preserve matching snapshot points from the prior public catalog and add current observations. When an individual snapshot or official observation is absent from an otherwise valid collection, its prior series and receipt time are retained with `stale` status; subsequent observations merge only when source and unit still match. These sparse snapshots are not a complete daily history. Independent providers and units remain separate even when their indicator names overlap. Stock and ETF instruments are excluded.

Economic series use reference period dates, not publication timestamps. The history series can contain revised official values; release-only series select the latest received version for each period and definition. The `releases` array retains individual version IDs, receipt timestamps, vintage and revision links; unknown publication times stay unknown. `events` selects the latest received schedule per event ID and preserves date versus time precision. Neither a reference period nor the catalog generation time is a release timestamp.

Model links include only actually observed forecast inputs whose date and value match the public chart series. Return ratios are checked against percent-return series after conversion; a level links to its level series. The 5- and 20-session returns require every intervening daily return to be verified, matching the web explorer. Each link includes the issuing publication and run identifiers, target and as-of dates, forecast ID and cutoff when available, so cached clients can verify identity before using it. Reconstructed or unavailable model rows are not represented as observed links.

## Native chart database

Both Pages workflows stage tracked files from `docs` and generate `data/market-indicators-v1.sqlite` beside `data/market-indicators-v1.manifest.json` in the deployment artifact. A local public build needs Python 3.11+ and the tracked catalog and seed.

```sh
python3 scripts/export_market_indicator_sqlite.py --output-dir /tmp/market-indicators-public
```

The manifest carries integer `schema_version` (1), UTC `generated_at`, `size_bytes`, and the lowercase SHA-256 of the complete SQLite file. Fetch the manifest first. A client can skip the database when its local version matches. Before replacing a local copy, check the file size, SHA-256, SQLite schema version and matching generation timestamp.

The SQLite file uses `PRAGMA user_version=1`. Table `meta(key,value)` holds `schema_version`, `generated_at`, the chart history's `as_of_date`, and `scope` (`public` in a Pages release). When a rebuild of the same catalog changes bytes, the staging script advances the publication time and records the original source time in `catalog_generated_at`. Table `series(id,metadata_json,first_date,last_date)` holds catalog metadata and the actual bounds of numeric evidence. `country` contains KR, US, JP or EA where known. `verified_through` carries the source's own cutoff where supplied. An absent value stays null. Chart points and explicit gaps are in `observations(series_id,date,value)`, indexed by the composite primary key. The `events`, `releases` and `model_links` tables each have `ordinal` and `payload_json` columns preserving the catalog order and fields.

The daily catalog carries prior observations that fell before the new window in its `observation_archive` for series whose ID, source, unit and date basis match. The archive also carries original release dates and URLs. The new window supplies current observations and corrections. The SQLite exporter combines this ledger with the current points and the reviewed public seed, with one row per series and date.

The initial Treasury seed in `data/chart_seeds/us_treasury_2021_2023.csv` contains percentages for the 1-, 3-, 5- and 10-year par yields from January 4, 2021 through November 27, 2023. The rows were read from `macro_series` for the exact `US_TREASURY_{1,3,5,10}Y` codes, source `us_treasury_daily_par_yield_curve`, revision 0. Each tenor had 727 earlier observations matching Treasury's CSV and 746 overlapping observations matching the public catalog. The source file's SHA-256 was `258a594eb64e9d21d9e8574b0b8580b0a5230dce56bb284ec6aa49a9a260897f`. [U.S. Treasury historical par yields](https://home.treasury.gov/system/files/276/yield-curve-rates-1990-2024.csv)

For local QA, add `--local-qa-sqlite /path/to/index_forecast.sqlite` and use an output directory outside a checkout. This reads older KOSPI and KOSDAQ closing levels through a read-only connection and marks the file `scope=local_qa`. The local series note identifies the dates awaiting source and redistribution review. The public exporter uses only its tracked inputs. When public generation fails, deployment can carry forward the previously published pair after verifying its digest, scope, metadata, schema and integrity. After the first release, staging validates the previously deployed pair before selecting either version. A missing or invalid fallback stops deployment before upload, preserving the live site. Only an HTTP 404 for the previous manifest permits a freshly generated first release.
